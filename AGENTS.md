# AGENTS.md

OAuth2 / OpenID Connect authentication server with WebAuthn (FIDO2), Go (see `go.mod` for the toolchain version), Gin + GORM/PostgreSQL + Redis.

## Commands

Task runner is [Task](https://taskfile.dev/) (`Taskfile.yml`), not Make. There is **no CI, no linter config, and no formatter config** in this repo — verification is `task build` + `task test`.

| Command | Notes |
|---|---|
| `task build` | `go build -tags=nomsgpack -o /dev/null` |
| `task test` | `go test ./...` |
| `task run-debug` / `task run` | Depends on `up-db` **and** `swagger`, so `swag` must be installed and Docker running |
| `task up-db` / `task down` | PostgreSQL + Redis via `docker-compose.yml` |
| `task swagger` / `task swagger-format` | `swag init` / `swag fmt` |

Always pass `-tags=nomsgpack` to `go build`/`go run`; omitting it diverges from the shipped build.

Focused testing:
```sh
go test -v -run TestSignUp ./api/...
go test -race ./...
```

Prerequisite not installed by the Taskfile:
```sh
go install github.com/swaggo/swag/cmd/swag@latest
```

The Taskfile also has many `test-*` tasks (`test-login`, `test-token`, `test-client-create`, ...). These are **manual cURL smoke tests against a running server**, not unit tests; most require `AUTH_DOMAIN` set and a `cookies.txt` produced by `task test-login`. There are also `db-*` tasks that run `psql` using the connection string in `keys/database_connection_string`.

## Architecture

- `main.go` — wiring only: Viper config (`cli.ConfigureViper("", "auth", ...)`), DB connect, `db.Migrate(dbConn)` (GORM AutoMigrate — **schema changes go in `db/model.go`, there are no migration files**), seed-user import, then `server.GetRouter(...)`.
- `server/route.go` — single `GetRouter` function with a very long positional parameter list; all routes and middleware groups live here. Adding a config knob means threading it through `main.go` → `GetRouter`.
- `api/` — Gin handlers, middleware, request/response models.
- `db/` — GORM models (`model.go`) and queries (`helper.go`).
- `store/` — go-oauth2 client store. `jwthelper/` — JWT signing.
- `docs/` — generated by `swag init`; do not hand-edit.
- `assets/` — frontend HTML/JS/CSS served when `AUTH_FRONTEND_ENDPOINTS=true`.
- Shared DB/CLI helpers come from the external module `github.com/alexhokl/helper` (there is a commented-out `replace` to `../helper` at the bottom of `go.mod`).

Route groups apply middleware explicitly, e.g. `api.WithDatabaseConnection(dialector)` (injects `db` into the Gin context) and `api.RequiredAdminAccess()` / `api.RequiredAuthenticated()`.

## Conventions

Error handling — use the helpers in `api/helper.go` rather than writing status codes inline:
`handleInternalError(c, err, msg)`, `handleBadRequest(c, err, msg)`, `handleUnexpectedError(c, err)`.

Handlers get the DB connection from context:
```go
dbConn, ok := getDatabaseConnectionFromContext(c)
if !ok {
    handleInternalError(c, nil, "Missing configuration for database")
    return
}
```

Logging is `log/slog` structured only: `slog.Error("msg", slog.String("error", err.Error()))`.

Imports are grouped: stdlib, then `github.com/alexhokl/auth-server/...`, then third party.

Test package naming is inconsistent by design: `api/*_test.go` use `package api` (they exercise unexported helpers); `db/` and `store/` use `package db_test` / `package store_test`. Match the package already used in the directory. DB tests use `go-sqlmock` with regex-matched queries; assertions use `testify/assert`.

Swagger comments (`@Summary`, `@Tags`, `@Router`, ...) are required on new endpoints; run `task swagger` afterwards and commit `docs/`.

## Environment

Config is Viper with prefix `AUTH_`; the authoritative list of what a working dev run needs is the `env:` block of the `run-debug` task. Secrets are read from **file paths**, not values: `AUTH_DATABASE_CONNECTION_STRING_FILE_PATH`, `AUTH_REDIS_PASSWORD_FILE_PATH`, `AUTH_PRIVATE_KEY_PASSWORD_FILE_PATH`. The `keys/` directory holds local dev keys/secrets; generate the signing key with `task gen-key` (requires `step`).

`localhost` is unsuitable for WebAuthn/OIDC testing — the README's Tailscale MagicDNS + Caddy setup (`task caddy`) is the intended path.

Admin bootstrap: on an empty `users` table the server imports `AUTH_SEED_USERS_FILE_PATH` (`import_users.json`); a user must have role `admin` to manage clients.
